# Decision Log — 정비구역·모아타운·노후도 지도 레이어

## DA-01. 폴리곤은 PostGIS에, 조인은 서버에서 사전계산 (2026-08-18, 사용자 결정)

- **결정**: 구역 폴리곤·단계·노후도 데이터를 tools/collector가 PostGIS에 적재(017_ 멱등 마이그레이션,
  스키마 소유권 collector 유지)하고, 물건×구역 point-in-polygon 조인을 서버측에서 사전계산해 물건이
  "구역 안 여부·구역명·단계"를 사실 컬럼으로 갖게 한다. NestJS API(controller/service/repository/DTO,
  외부 응답 zod 검증)가 서빙하고, 웹은 apps/web 기존 map 모듈 안에서 TS로 렌더한다(D-010 어댑터 방향).
  색상은 packages/design-tokens 토큰만, 문구는 D-011 사실 서술만.
- **기각한 대안**: 작업지시서의 정적 `zones.geojson` + 프론트 단독 렌더(`fetch-zones.mjs`/`zones-layer.js`,
  런타임 API 0회).
  - 대안의 장점(솔직 기록): 구현 최소(스크립트 2개+1줄), DB 마이그레이션 불필요, 배포 후 외부 의존성 0
    (오프라인·장애 내성), 네트워크 탭 검증이 단순.
  - 기각 사유: ① 사실이 지도 화면에 갇힘 — 목록·상세·모바일·WP-11 백테스트가 재사용 불가
    ② 서울 전역 폴리곤을 통으로 브라우저에 태우면 페이로드가 커지고(수 MB급), bbox·단순화 서빙이 불가
    ③ 이 레포는 PostGIS+GIST가 이미 가동 중이라 "로컬 파일 캐시"의 단순성 이점이 작음
    ④ 바닐라 JS 전제(`drawZones(map)` 1줄) 자체가 이 코드베이스에 존재하지 않음
    ⑤ 갱신이 "스크립트 재실행+재배포"가 되어 단계 신선도 관리와 충돌.
- 근거: 코디네이터 경유 사용자 확정 통보(2026-08-18). 관련 규칙: AGENTS.md 2·3·21, tools/collector CLAUDE.md.

## DA-02. 지시서의 판정 프레임("초록=검토 대상, 빨강=패스") 폐기 (2026-08-18)

- **결정**: 단계별 색은 "단계 구분"의 시각 인코딩으로만 쓰고, 화면 문구는 사실+쉬운 설명만 쓴다.
  예: "이 물건은 ○○구역 안에 있어요 · 조합설립인가(2024-03-11 고시)" + "조합원 자격 승계 기준은
  도시정비법 제39조에 있어요" + 조문 링크. 그 이상은 쓰지 않는다.
- **정정 (2026-08-19, 08 리포트 m-19)**: 초판의 예시 문구는 "조합설립인가가 나면 일부 지역·사업
  유형에서는 소유권을 넘겨받아도 조합원 자격이 함께 넘어오지 않는 경우가 있어요"였다. 판단·권유
  어휘가 없어 SC-004 금칙어 테스트에는 절대 걸리지 않지만, **개별 물건 맥락에서 제39조의 효과를
  설명**하는 문장이라 PRD non-goal("조합원 승계 가부 판정 포함 금지")과 긴장 관계다. 금칙어 테스트가
  잡을 수 없는 종류의 위반이므로 **예시 자체를 조문 링크로 축소**한다. 규칙: 화면은 ①구역명 ②단계
  원문+쉬운 뜻풀이 ③고시일 ④출처·기준일 ⑤조문 링크까지만 쓰고, **조문의 적용 결과는 어떤 형태로도
  서술하지 않는다.** 이 규칙은 06 TS-23의 검사 대상 문구 상수 전체에 적용된다.
- 사유: ① D-011/변호사법 §109 — 판단·권유 문구 금지 ② 법리적으로도 이분법이 부정확(양도 제한은
  투기과열지구 여부·사업유형·예외조항 의존 — 01-recon §1) ③ 색 선례: usage-category.ts가 구분색에서
  warning/critical 토큰을 의도적으로 회피 — 같은 원칙 적용.

  본 프로젝트에 적용되지 않는다. DA-03의 "상용 부적합" 판정 사유는 소멸.
- **재평가 결과 — 그래도 폴리곤 1순위는 토지이음(eum.go.kr) 정비구역정보 SHP 유지.** 사유 교체:
  1. **존재가 검증됨**: 토지이음 SHP는 실제 다운로드 항목 확인(최근 2026-07-23). 브이월드 데이터 API의
     `LT_C_UPISUQ153`은 공식 레퍼런스에서 확인 실패 — API 제공 여부 자체가 미검증. 설계의 P0 경로를
     미검증 엔드포인트에 걸 수 없다.
  2. **원천 정합성**: 정비구역 경계의 법적 원천은 지형도면 고시(국토이용정보체계)이고 토지이음이
     그 직배포 창구다. 모아타운 지정구역(소규모주택정비 관리지역)도 같은 체계에 있어 소스가 통일된다.
  3. **수집기 궁합**: 월간 파일 배치는 기존 collector의 파일·배치 구조와 맞고, API 폴링·쿼터 관리가 없다.
- **브이월드는 대체 경로로 승격** (기각 아님): 데이터 API는 자동화가 가장 쉬우므로(HTTP GET·JSON·
  bbox/attrFilter), 임포터를 소스별 어댑터로 나누고 `zone_source` 컬럼으로 병존 가능하게 설계한다.
  브이월드 채택 시 **착수 전 선행 조건**: 인증키 발급 후 실제 레이어 목록 대조로 `LT_C_UPISUQ153`
  존재·속성 스키마를 실조회 검증할 것 (레퍼런스 문서만으로 단정 금지).
- **ND(변경금지) 잔존 리스크 — 단정하지 않고 기록**: 좌표변환·단순화·합집합 산출물을 화면에 표시하는
  것이 "변경물 배포"에 해당하는지는 해석 여지가 있다. CC의 ND는 변경물의 *공유*를 제한하고 사적
  이용은 허용하므로, 이용자가 개발자 본인뿐인 현 단계에서는 실질 리스크가 낮다. 타인 제공(배포) 시점에
  재평가 필요. 텍스트 사실 표기는 저작물 이용이 아니어서 어느 경로든 안전. (근거: CC BY-NC-ND 요약

## DA-13. 신속통합기획·가로주택·재정비촉진 편입과 모아타운 복귀 — OA-22712 채택 (2026-08-20)

사용자 요청("노후도랑 모아, 신통, 가로주택 표시하는 기능")으로 구역 종류 확장을 검토했다.
**기획을 늘리기 전에 원천 실사를 먼저 했다** — 이 패키지가 두 번 실패한 순서를 반복하지 않기 위해서다.
실사 결과는 `10-recon-additional-zones.md`.

### 채택: OA-22712 (서울플랜+ 공간정보)

**네 종류의 폴리곤이 이 한 파일에 다 들어 있다.** 실제로 내려받아 DBF 2,585행을 파싱해 확인했다.

- 형식: SHP zip 2.24MB, 반기 갱신, 공개 2025-09-05 / 갱신 2026-02-11
- 라이선스: 공공누리 **4유형**(출처표시+상업적이용금지+변경금지) — DA-12의 비영리 전제에서 사용 가능
- **익명 다운로드 실측 성공** — `POST datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do`.
  브이월드 30335가 로그인을 요구해 수동 취득(DA-09)인 것과 **결정적으로 다르다**. 자동화된다.
- 속성에 `SCLAS_CL`(사업유형)·`PROPEL_CD`(추진단계)가 있어 **단계별 색상 요구사항(FR-005)과 축이 같다**
- 동봉된 `서울플랜+코드정의표(대민용).xlsx`가 코드 정의를 준다 — 매핑 사전을 추측하지 않아도 된다
- 고지: "**법적 효력이 없으며 참고자료로만 활용 가능**" → 사용자 대면 문구에 그대로 표기한다(D-011)

### DA-05R 부분 폐기 — 모아타운 폴리곤은 존재한다

DA-05R은 "개방 SHP가 존재하지 않음"을 근거로 FR-007을 P1 → P2로 강등했다.
**정확한 사실은 "찾던 카탈로그에 없었다"이다.** 브이월드·토지이음에 없다는 원근거는 2026-08-20
재확인에서도 유효하지만, OA-22712가 그 두 카탈로그 밖에 있었다.

→ **FR-007을 P1으로 되돌린다.** 폴백이던 FR-013(고시문 필지조서 재구성)은 불필요해졌다.

### 우선순위

| 대상 | 판정 | 근거 |
|---|---|---|
| 모아타운 (FR-007) | **P1 복귀** | 폴리곤 106(관리지역고시 52), 단계 PP0401~0406 |
| 재정비촉진지구 (신규 FR-018) | **P1** | 지구 31 + 촉진구역 213. 규모가 작고 단계 축이 있다 |
| 가로주택정비 (신규 FR-019) | **P2** | 폴리곤 729인데 **491이 "연번부여 추진중"** — 초기 단계를 구역처럼 그리면 오해를 만든다 |
| 신속통합기획 (신규 FR-020) | **P2** | **법정 구역이 아니다.** 구역지정에 도달하면 기존 P0(정비구역)에 자연히 포함된다 |

가로주택·신통을 P2로 두는 이유는 원천이 없어서가 아니라 **표시 가치 대비 오해 위험**이다.
"사실만 서술한다"(D-011)는 원칙에서, 확정되지 않은 사업지를 구역과 같은 무게로 그리면
사용자가 확정 구역으로 읽는다.

### 설계 파급

**임포터 하나 + 사업유형 필터**로 네 종류를 다 덮는다. 구역 종류는 `SCLAS_CL` 기반 열린 값으로
두고(FR-004의 `kind` 필터 확장), 새 종류를 넣을 때 스키마를 건드리지 않게 한다.

**주의**: OA-22712의 좌표계가 기존 30335(EPSG:5186)와 다르다 — PRJ가 Bessel 중부원점 계열이다.
적재 시 pyproj로 확인해야 하고, 추측으로 5186을 넣으면 전국이 어긋난다.

### 남은 미확인

`10-recon-additional-zones.md` §8에 7건. 대부분 인증키·계정 발급(사용자 액션)이 선행이다.
특히 정보몽땅 엑셀(가로주택 목록·단계)은 **공공누리 표시 자체가 없어** 라이선스가 불명이다 —
FR-019를 착수할 때 서울시 문의가 선행 조건이다.
