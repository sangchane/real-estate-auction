# PRD — 정비구역·모아타운·재정비촉진·가로주택·신통·노후도 지도 레이어

## 배경 (RECON 요약)

경매 탐색자는 물건이 정비구역(재개발·재건축) 안인지, 어느 인가 단계인지, 주변이 얼마나 노후한지를
사실로 알고 싶어 한다. 규모 실측(2026-08-19): **서울 정비사업 구역 472개**(단계 원천
`TbSeoulRedevStatus`의 `list_total_count`), **모아타운 대상지 132개소**(2026-03 기준, 공모 88 +
주민제안 44), 서울 건축물 표제부 수십만 동. **모아타운 "지정 구역" 수는 공식 집계가 없어 미확인**이다
(초판의 "지정 85곳"은 정비구역 전략사업 85개 구역과 혼동한 수치 — 삭제, DA-05R). 경계의 법적 원천은
지형도면 고시(국토이용정보체계)다. 원 작업지시서의 "초록=검토 대상, 빨강=패스" 판정 프레임은
D-011(변호사법 §109) 위반이자 법리적으로도 부정확하여 폐기하고(DA-02), 사실 서술로 재설계한다.
아키텍처는 사용자 결정으로 PostGIS 적재 + 서버측 사전계산 확정(DA-01).
**비영리 전제 확정(DA-12, 2026-08-20 사용자 결정)** — `00-seed`의 "상용 서비스 전제"는 폐기했다.
이 전제 위에 NC 계열 원천(30335·OA-22712·30337)이 서 있으므로, 수익화가 논의되면
데이터원 선정 전체가 재점검 대상이다. 퇴로와 절차는 DA-12의 상용 전환 체크리스트에 적어 두었다.
**데이터원은 GATE 2차에서 전면 재확정됐다 — 폴리곤=브이월드 dsId=30335(DA-03R2), 단계=서울
열린데이터광장 OA-22856 Open API(DA-04R), 모아타운 지정 폴리곤은 원천 부재로 P2 강등(DA-05R).**

## 제품 목표 (≤3, 직교)

1. **위치 사실의 시각화**: 지도에서 정비구역·모아타운의 경계(또는 위치)와 추진 단계를 물건과 겹쳐 볼 수 있다.
2. **물건 단위 사실 제공**: 각 물건이 "어느 구역 안인지·단계·주변 동 노후도"를 상세·목록·백테스트가 재사용 가능한 DB 사실로 갖는다.
3. **신선도 유지와 정직한 공백**: 단계·노후도는 **사람 손 없이** 주기 갱신된다(공개 API). 폴리곤 원천은
   로그인 다운로드만 제공하므로 **월 1회 수동 취득(파일을 드롭 폴더에 넣기) + 이후 전 과정 자동**이
   기본 경로다(DA-09 — 사람 승인 대기). 어느 쪽이든 **불확실한 값은 표시하지 않는다(허위 0)**.

## 엣지케이스 (Given/When/Then)

**흐름 A — 공간 조인·표시**
- A-1: Given 물건이 재정비촉진지구와 세부 정비구역에 동시에 겹침 / When 사실 계산 / Then `auction_item_zone`에 두 행 모두 저장되고 상세에 두 구역이 모두 표기된다(대표 1개 선별 금지 — 선별이 곧 판단).
- A-2: Given 물건 geom이 NULL / When 조인 배치 / Then 그 물건은 조인 대상에서 제외되고 상세는 구역 사실 섹션을 표시하지 않는다("구역 밖"이라고 말하지 않는다 — 모르는 것과 밖인 것을 구분).
- A-3: Given 폴리곤 경계선 위의 물건 / When ST_Intersects 판정 / Then 포함으로 기록한다(기준을 API 문서에 명시).
- A-4: Given 줌 12에서 서울 전역 bbox 요청 / When 폴리곤 조회 / Then 단순화 허용오차가 커진 지오메트리로 응답 크기 512KB 이하를 지킨다.

**흐름 B — 단계 동기화**
- B-1: Given 정규화 후 같은 자치구에 동명 후보 2건 / When 매칭 / Then 매칭하지 않고 "단계 미확인" + 리포트에 후보 2건 기록.
- B-2: Given `TbSeoulRedevStatus` 응답에서 필수 필드(`DISTRICT`·`ZONE_NM`·`BIZ_TYPE`·`BIZ_STAGE`) 누락(스키마 변경) / When 검증 / Then 동기화 중단·알림, 기존 단계 데이터와 화면 표시는 유지(스테일 명시: 기준일 표기).
- B-6: Given 응답의 `BIZ_STAGE`가 단계 사전에 없는 새 값 / When 매칭 / Then 그 구역은 **"단계 미확인"** 으로 두고(임의 버킷 배정 금지) `stage_match_report`에 원문을 기록한다 — 사전 갱신은 사람이 코드+테스트로 한다.
- B-3: Given 수동 별칭(zone_alias)이 등록된 구역 / When 다음 주간 동기화 / Then 별칭 매칭이 자동 계산 결과보다 우선하고 동기화가 별칭을 수정·삭제하지 않는다.
