# 유찰 회차별 권리분석 특징 조사

- 작성일: 2026-08-31 (데이터 기준 시각: 같은 날 조회)
- 목적: 유찰 횟수와 매각물건명세서 기반 권리분석 특징 사이에 관계가 있는지, 있다면 어떤 형태인지 실측.
- 발단이 된 요청(2026-08): "유찰 5회 이상이면 권리분석상 문제가 많을 것이고, 2~3회 미만 낙찰이면
  하자가 없을 가능성이 높다" → 이후 지시로 **두 그룹 비교가 아니라 회차별 통계**로 재설계했다.
- 이 문서는 사실 서술과 규칙 ID만 담는다. 판단·권유 표현은 쓰지 않는다(D-011, 변호사법 §109).
  여기 쓴 문구가 화면으로 흘러갈 수 있음을 전제로 썼다.

## 1. 한 줄 결론

**관계는 있으나 선형이 아니라 문턱형이고, 방향은 항목별로 갈린다.** 대항력 요건을 갖춘 임차인이
있는 물건의 비율은 유찰 0~4회에서 52~63%로 평탄하다가 **5회부터 77%, 7회 이후 92~98%로 포화**된다
(0~2회 58.9% vs 9~11회 95.5%, Spearman ρ=+0.178). 반면 **매각 쪽은 가설과 반대다** — 관측 창 안에서
대항력 임차인이 있는 물건이 없는 물건보다 낙찰률이 낮지 않았고(0~2회: 29.1% vs 22.1%), 0~2회차에
낙찰된 물건의 대항력 보유율(81.8%)이 같은 회차 미낙찰 물건(75.7%)보다 오히려 높았다.
즉 "유찰이 적게 끝난 물건 = 대항력·특이사항 하자가 없는 물건"은 이 데이터에서 지지되지 않는다.
2026-07-29 사용자 경고("인수 부담이 있어도 가격이 빠지면 낙찰된다")와 정합한다.

## 2. 조사 설계

### 2-1. 표본 프레임

- 모집단: `auction_item` 중 `failed_bid_count`가 있고, **최신 명세서**(물건당
  `document_date DESC, id DESC` 1건)에 `baseline_date`(말소기준)가 있는 물건.
- 조회 시점 프레임: **4,160물건**. 여기서 `2025타경859`(서울서부, 상가 362물건 단일 사건)를
  제외해 **3,798물건**으로 분석했다(§2-4). 발주 시 전달받은 회차별 표본 수(0회 670 …)와 수십 건
  단위 차이가 있는데, (a) "최신 명세서 1건" 선택 기준 차이와 (b) 수집이 계속 돌아 데이터가 늘어난
  것이 원인이다. 이 문서의 분모는 전부 조회 시점 기준으로 다시 센 값이다.
- 회차: `failed_bid_count` 0~11은 각각(모두 56건 이상), **12회 이상은 "12+"로 묶음**(91건,
  개별 회차는 1~26건뿐이라 따로 내지 않는다).
- 매각 결과: `auction_sale_result`에서 `dxdy_kind_code='01'`(매각기일 행만) +
  `dxdy_date >= 2026-07-31`(관측 시작, 생존 편향 컷) — `tools/backtest/CLAUDE.md` 함정 3종 준수.
  실제 창에 잡힌 기일은 2026-08-03 ~ 2026-08-28(매각기일 행 3,195, 낙찰 행 780).
  일괄매각은 사건당 1단위로 dedupe했다(WP-11 §4-2).

### 2-3. 2026-07-29 경고와의 긴장을 어떻게 다뤘나

WP-11 §2 첫머리의 경고 — *"유찰횟수만으로 좋은 물건으로 보지 마라. 인수 부담이 있어도 그만큼
가격이 빠지면 메리트가 생겨서 낙찰된다"* — 는 이번 요청("유찰 많음 = 권리 문제")과 긴장 관계다.
그래서 **두 방향을 분리해서 쟀다**.

1. **재고(stock) 방향**: 지금 n회 유찰 상태로 남아 있는 물건의 권리 특징 (§3).
2. **매각(flow) 방향**: 관측 창 안에서 권리 특징이 낙찰 여부를 갈랐는가 (§4, §5-3).

1에서 관계가 보여도 2에서 안 보이면, 그것은 "권리 특징이 유찰을 쌓는 것과 별개로, 저감된 가격이
그 부담을 흡수한다"는 경고 쪽 해석이 맞다는 뜻이다. 실측 결과가 정확히 그 조합이었다.

또 하나: `failed_bid_count`와 `minimum_sale_price/appraisal_amount`는 회차당 20% 저감으로
기계적으로 연동되므로 **최저가율을 독립 변수로 쓰지 않았다**. 역으로, 유찰 5회 이상 897물건 중
116건(12.9%)은 최저가율이 90% 이상이다 — 재감정으로 최저가가 리셋된 물건(§4-16의 함정)이라,
유찰 횟수를 "얼마나 싸졌나"의 대리지표로 읽으면 이 116건에서 틀린다.

### 2-4. 단일 사건 오염 제거

회차 1의 첫 집계가 이상했다(대항력 33.7%, 보증금비율 중위 0.06). 원인은
**`2025타경859`(서울서부) 한 사건이 상가 362물건**으로 회차 1 칸의 35%를 차지한 것이다.
한 건물의 호실들이라 권리 구조가 동일해, 물건 단위 집계에서 한 사건이 한 회차를 지배한다
(§4-2 일괄매각 함정과 같은 계열). 이 사건을 제외하고 모든 표를 다시 냈다. 제외 전 Spearman
ρ(대항력)=+0.244 → 제외 후 +0.178로, **제외 전 수치는 관계를 부풀린다.**
같은 이유로 회차 3의 플래그 급등(§3-3)도 다물건 사건 클러스터임을 확인해 표에 주석을 달았다.

## 4. 유찰 0~2회 낙찰 그룹의 프로파일 (매각 방향)

관측 창(2026-07-31~) 안에서 결과가 붙은 매각 단위 중 `failed_bid_count` 0~2 물건.
분모가 지표마다 다르므로 각 줄에 명시한다.

| 지표 | 낙찰 (376단위) | 미낙찰 (1,006단위) |
|---|---|---|
| 대항력 있음 / (임차인표+기준일 판정 가능) | 242/296 = **81.8%** | 591/781 = **75.7%** |
| 보증금합계 > 감정가 / (임차인 있음) | 92/306 = **30.1%** | 174/822 = **21.2%** |
| HUG_PRIORITY_WAIVER / 전체 | 35/376 = 9.3% | 140/1006 = 13.9% |
| `assumed_rights_kind = NONE` / 전체 | 20/376 = 5.3% | 67/1006 = 6.7% |
| `assumed_rights_kind` 공란 / 전체 | 289/376 = 76.9% | 687/1006 = 68.3% |

- **"유찰 없이·적게 낙찰된 물건은 대항력 등 하자가 없을 가능성이 높다"는 가설과 반대 방향이다.**
  빨리 낙찰된 물건의 대항력 보유율이 미낙찰보다 6.1%p 높다(z≈2.1). 보증금이 감정가를 넘는
  물건 비율도 낙찰 쪽이 8.9%p 높다.
- 같은 표를 낙찰률 방향으로 읽으면(동일 2×2): 0~2회차에서 대항력 있는 물건의 창 내 낙찰률
  29.1%(833단위 중 242) vs 없는 물건 22.1%(244단위 중 54). 3~4회차도 같은 방향이다
  (36.7% vs 29.3%). 5회+ 구간은 대항력 없음 쪽이 25단위뿐이라 판단하지 않는다.
- 해석 주의: 이것은 인과가 아니라 구성 효과일 수 있다 — 대항력 임차인은 주거 소형 물건에
  몰려 있고, 그 유형이 창 안에서 더 잘 팔렸다. 어느 쪽이든 "대항력 존재가 조기 낙찰을
  막는다"는 명제는 이 데이터에서 성립하지 않는다.
- 참고로 유찰 5회+ 낙찰 120단위도 최소 97단위(80.8%)에 대항력 임차인이 있다. 대항력이 있어도
  팔린다 — 회차별 중위 낙찰가율 5.5~73.9% 구간에서(§5-1 표).

## 6. 데이터로 판정 불가한 것

1. **등기부 미연동**: 근저당·가압류·전세권 등 등기 권리의 금액과 순위가 없다(등기부는 현재
   10건 남짓). 따라서 "인수액"을 계산할 수 없고, 이 문서의 대항력은 **요건 충족 여부**까지만이다.
   H2·H5·H6이 막혀 있는 것과 같은 이유.
2. **배당요구 공란 문제(§4-26)**: `demanded_distribution`은 지금도 NULL 6,256 / true 3,779 /
   **false 0**이다. "대항력 있음 + 배당요구 안 함 = 보증금 전액 인수"의 확정 판정이 구조적으로
   나오지 않는다. §3의 대항력 비율을 인수 확정 비율로 읽으면 안 되는 두 번째 이유.
3. **`OTHER`·공란의 내용**: 자유서술 원문을 DROP(006)했으므로 `OTHER` 급증(고회차 17~37%)이
   무엇인지 사후 확인 불가. 공란은 법원 관행과 얽혀 있다(§3-2 주의 2).
4. **유입 vs 생존 분해 불가**: 이 조사는 단면(cross-section)이다. 고회차 재고의 대항력 94%가
   "대항력 물건이 안 팔려 남은 것"(생존)인지 "2023~24년 전세사기 물건이 대량 유입된 것"(유입)
   인지 현재 데이터로 가를 수 없다. 코호트 추적(§7의 H11)이 필요하다.
5. **시세 부재**: 보증금비율·낙찰가율의 분모가 감정가다. 감정 시점·방식에 따라 시세와 괴리가
   있고, 특히 재감정 물건(5회+ 897건 중 116건)은 비교 기준 자체가 바뀐다.
6. **응찰자 수 없음(§1-1, §4-17)**: 경쟁 강도를 직접 잴 수 없어 낙찰 여부·낙찰가율로 대리한다.
7. **관측 창 1개월**: 매각 방향 수치(§4, §5-1)는 2026-08-03~08-28 창의 것이다. 계절성·시장
   국면은 통제되지 않았다.

## 8. 재현 방법

읽기 전용. 물건 단위 프레임을 아래 SQL로 뽑고, 회차별 집계와 Spearman은 파이썬에서 계산했다
(스크립트 전문은 세션 스크래치에 있었으므로 아래에 집계 절차를 함께 적는다).

### 8-1. 물건 프레임 SQL

```sql
WITH ln AS (
  SELECT DISTINCT ON (auction_item_id) *
  FROM auction_item_notice
  ORDER BY auction_item_id, document_date DESC NULLS LAST, id DESC
), raw AS (
  SELECT DISTINCT ON (auction_item_id) auction_item_id, payload
  FROM auction_item_raw ORDER BY auction_item_id, observed_at DESC
), dep AS (
  SELECT notice_id, sum(deposit_amount) AS dep_sum
  FROM (SELECT DISTINCT notice_id, deposit_amount, move_in_date
        FROM auction_item_notice_tenant
        WHERE deposit_amount IS NOT NULL AND deposit_amount < 100000000000) d
  GROUP BY 1
), ten AS (
  SELECT notice_id, count(*) AS rows FROM auction_item_notice_tenant GROUP BY 1
), opp AS (
  SELECT t.notice_id, bool_or(t.move_in_date < n.baseline_date) AS any_opp
  FROM auction_item_notice_tenant t
  JOIN auction_item_notice n ON n.id = t.notice_id
  WHERE n.baseline_date IS NOT NULL
  GROUP BY 1
)
SELECT i.id, ca.case_no, i.failed_bid_count AS fbc,
       split_part(r.payload->>'dspslUsgNm', ',', 1) AS usage,
       COALESCE(r.payload->>'mulBigo','') LIKE '%일괄%' AS bulk,
       i.appraisal_amount,
       n.assumed_rights_kind AS kind,
       COALESCE(n.risk_flags, '{}') AS flags,
       n.tenant_scanned_at IS NOT NULL AS scanned,
       n.tenant_rows_rejected AS rejected,
       COALESCE(ten.rows,0) AS trows,
       COALESCE(opp.any_opp,false) AS opp,
       dep.dep_sum
FROM auction_item i
JOIN auction_case ca ON ca.id = i.auction_case_id
JOIN ln n ON n.auction_item_id = i.id
LEFT JOIN raw r ON r.auction_item_id = i.id
LEFT JOIN ten ON ten.notice_id = n.id
LEFT JOIN opp ON opp.notice_id = n.id
LEFT JOIN dep ON dep.notice_id = n.id
WHERE i.failed_bid_count IS NOT NULL AND n.baseline_date IS NOT NULL;
```

### 8-2. 매각 결과 SQL

```sql
SELECT auction_item_id, bool_or(result_code='001') AS sold, max(sale_amount) AS sale_amount
FROM auction_sale_result
WHERE dxdy_date >= DATE '2026-07-31' AND dxdy_kind_code = '01'
GROUP BY 1;
```

### 8-3. 집계 절차 (파이썬)

1. `2025타경859` 사건의 행 제외 (§2-4).
2. 회차 `r = LEAST(fbc, 12)` (12 = "12+").
3. `tenant_known = trows > 0 OR (scanned AND rejected = 0)` — §4-23 게이트.
4. `dep_ratio = dep_sum / appraisal_amount` (분모: `trows>0 AND dep_sum·감정가 존재`).
5. 매각 단위: 결과가 붙은 물건 중 `bulk`이면 `case_no`, 아니면 물건 id로 DISTINCT
   (낙찰 우선 유지). 낙찰가율은 비일괄 낙찰 단위만 `sale_amount / appraisal_amount`.
6. Spearman: 두 변수 모두 평균 순위(rank, 동점은 평균)로 바꾼 뒤 Pearson 상관.
   이항 지표는 0/1 그대로 순위화한다.
7. 회차별 표는 각 회차에서 위 지표의 분자/분모를 그대로 센 것이다.

### 8-4. 검증용 부속 쿼리

- 단일 사건 오염 확인: 프레임에서 `GROUP BY case_no ORDER BY count(*) DESC` — 최대 사건이
  `2025타경859`(362물건)임을 확인.
- 회차 3 플래그 클러스터 확인: `WHERE failed_bid_count = 3 AND (플래그 3종 중 하나) GROUP BY case_no`.
- 재감정: `SELECT count(*) FROM auction_item WHERE failed_bid_count >= 5 AND
  minimum_sale_price::numeric / NULLIF(appraisal_amount,0) >= 0.9` → 116/897.
- §4-26 확인: `SELECT demanded_distribution, count(*) FROM auction_item_notice_tenant GROUP BY 1`
  → NULL 6,256 / true 3,779 / false 0.
