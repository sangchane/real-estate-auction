# Seed — 정비구역·모아타운·노후도 지도 레이어 (redevelopment-zone-overlay)

- 원문:
  - 사용자 작업지시서(요약): 기존 경매 지도에 서울 정비구역 폴리곤을 단계별 색상으로 오버레이.
    브이월드 API 1회 다운로드 → `zones.geojson` 로컬 캐시 → 네이버지도 폴리곤 렌더 →
    구역명→단계 수동 매핑(STAGE 테이블) → 클릭 시 구역명·단계 표시.
    판정 기준: "초록(인가 전) 안이면 검토 대상, 빨강(인가 후) 안이면 조합원 승계 불가로 패스".
  - 추가 요청(원문 그대로): "쉽게 말해서 모아타운이나 주변 노후도 같은것도 표현해줄 수 있는 기능도 있으면 좋겠어"
- 서비스 유형: 복합 — 웹 SaaS(지도 UI 기능 추가) + 데이터 파이프라인(외부 공공데이터 수집·적재·집계)
  - 모바일 앱(RN)에 동일 지도 화면(MapHomeScreen)이 존재 → 모바일 파급 여부가 범위 결정 사항
- 주 도메인: 부동산 경매 탐색 (기존 플랫폼의 지도 화면 확장)
- 인접 도메인: 도시정비(재개발·재건축 추진 단계), 소규모주택정비(모아타운/모아주택),
  건축물대장 기반 노후도 통계, 공공 공간데이터(브이월드/서울 열린데이터광장/정보몽땅)
- 감지된 제약:
  1. 작업지시서가 **바닐라 JS 앱 전제**로 작성됨 — 이 코드베이스(Next.js 16 + TS strict,
     `apps/web/app/items/map/MapView.tsx`)와 불일치. `drawZones(map)` 진입점 없음. → 지시서는 비평 대상 입력.
  2. 지시서의 판정 문구("검토 대상"/"패스")는 **D-011(변호사법 §109) 위반** — 사실 서술로 재설계 필수.
  3. 색상 하드코딩(#1e7a4f 등) 금지 — `packages/design-tokens` 토큰만 (usage-category.ts 선례:
     구분용 색에 warning/critical 토큰 회피).
  4. 지도는 어댑터 규칙(D-010)이 명목상 있으나 현 MapView는 naver.maps 직접 호출 — 현실과 규칙의 간극 존재.
  5. DB는 PostGIS 3.6 가동 중, `auction_item.geom(Point,4326)` + GIST 인덱스 — 정적 GeoJSON 대안으로
     서버측 공간 조인이 가능한 환경.
  6. 브이월드 키 미보유(사용자 사전 준비 필요). `DATA_GO_KR_SERVICE_KEY`는 보유.
  7. 수집기(tools/collector)가 스키마 소유, 마이그레이션은 멱등 필수, 다음 번호 017_.
  8. 상용 서비스 전제 → 각 데이터셋의 재배포·표시 의무(공공누리 유형) 확인 필요.
- 로드할 블라인드스팟 프로파일: P2(웹 SaaS) + P6(데이터 파이프라인) 합집합, P4(모바일)는 파급 항목만
