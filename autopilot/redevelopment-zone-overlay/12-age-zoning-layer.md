# 12 — 노후도·용도지역 지도 레이어 (FR-014 구체화 + 용도지역 신규)

작성 2026-08-31. 사용자 요청: "노후도, 몇종지인지도 필터나 버튼 클릭하면 지도상에 색상등으로
구분 가능하게". 01-recon·10-recon의 원칙을 따른다 — **직접 열어 본 URL만 사실로 적고**, 실파일은
내려받아 바이너리(DBF·xlsx)를 직접 파싱했으며, 확인 못 한 것은 §7 미확인 목록에 남겼다.
카탈로그 요약(WebFetch)은 쓰지 않았다 — B-2 오귀속(요약 모델 허위 생성)의 재발 방지.

## 0. 한 줄 요약

지도에 **채움(면) 레이어 2종**을 추가한다 — ① 법정동 노후도 코로플레스(FR-014 구체화),
② 용도지역(제1종~준주거 세분) 레이어(신규 FR-021·022). **용도지역 원천은 서울 열린데이터광장
OA-21136으로 실재·실측 확인**했고 인증키·계정 없이 자동 취득된다(즉시 착수 가능). 노후도는
기존 선행 조건(브이월드 계정 → 법정동 경계 FR-017, 세움터 원천 A-V1 → 집계 FR-009)이 그대로
선행이며, **지금 `building_age_dong`은 0행**이라 구간(bin)은 적재 후 분포 실측으로 확정한다.

## 1. A. 노후도 레이어 (FR-014 구체화)

데이터: `building_age_dong`(마이그레이션 021 실재, 현재 0행) — `total_count`(분모) /
`over20_count` / `over30_count` / `unknown_apr_count` / `base_ym`. 비율은 저장하지 않고 조회 시
계산한다(05 데이터 규칙). 경계: `bjd_dong`(FR-017, 역시 0행). API: EP-4
`GET /api/map-layers/building-age`(05에 P2로 이미 정의됨 — 이 문서가 그 명세를 채운다).

### 1.1 어떤 값을 색으로 쓰는가

- **채색 값은 한 번에 하나** — 기본 **30년 이상 비율**, 범례 안의 스위치로 **20년 이상 비율**로
  전환한다. 두 값을 동시에 칠하면(이중 인코딩) 읽을 수 없다.
- 기본을 30년으로 두는 이유는 판단이 아니라 **원천 사실의 형태**다: DA-07이 두 임계값을 병기하는
  이유 자체가 "법정 노후·불량 기준이 20~30년 범위라 단일 임계값 단정이 곧 판단"이기 때문이고,
  지도는 하나만 칠할 수 있으므로 더 보수적인(느리게 차오르는) 30년을 기본으로 하고 전환 수단을
  항상 노출한다. **클릭 카드와 물건 상세(FR-010)는 두 값을 병기**한다 — DA-07 원칙 유지.
- 비율 = `over30_count / total_count` (또는 over20). 계산은 API 한 곳(EP-4)에서, 소수점 1자리 %
  (05 반올림 정책 계승).

### 1.2 구간(bin) 정책 — 지금 확정하지 않는다

`building_age_dong`이 0행이라 **지금 경계값을 정하는 것은 전부 추측**이다. 정하는 것은 절차다.

1. **구간 수 5** + "집계 없음" 1 (범례 스와치 6개 — 코로플레스 관례상 5±2, 팔레트도 5스텝 §4).
2. **확정 절차**: FR-009 최초 적재 후 SQL로 서울 법정동별 over30 비율의 P10/P25/P50/P75/P90
   분위수를 실측하고, 그 근방의 **라운드 경계**(예: 20%, 40% 같은 읽기 쉬운 값)로 확정한다.
   분위수를 그대로 쓰지 않는 이유: 범례의 경계값은 사람이 읽는 숫자라서 소수점 분위수는 소음이다.
3. **20년/30년은 경계를 따로 확정**한다 — 두 분포는 다르다(20년 비율이 항상 크거나 같다).
4. 확정된 경계는 웹 순수 함수 상수(`zone-style.ts` 관례를 따르는 신규 `age-style.ts`)에 두고
   경계값 단위 테스트를 붙인다(SC-009 관례). **경계 변경은 코드+테스트로만** — stage 사전과 같은 원칙.

### 1.3 결측·저신뢰 처리

| 상황 | 처리 | 이유 |
|---|---|---|
| `total_count = 0` 또는 행 없음 | **채색하지 않음**(fill 없음, 동 경계선만) + 범례 "집계 없음" 항목 | 0%로 칠하면 "노후 건물 없음"이라는 **허위 사실**이 된다(엣지 C-2, 021 컬럼 주석과 동일) |
| `unknown_apr_count`가 큰 동 | 커버리지 = `total_count / (total_count + unknown_apr_count)`를 정의하고, **컷라인 미만이면 "집계 부족"으로 채색 제외**(집계 없음과 같은 렌더, 카드 문구는 다름). 컷라인 후보 70% — **확정은 분포 실측 후**(§7 U-J) | 결측이 절반인 동의 비율은 비율이 아니다. 낮은 신뢰 값을 진한 색으로 칠하는 것이 가장 나쁜 결과 |
| 컷라인 이상인 동 | 채색하되 **클릭 카드에 결측 수를 항상 표기** | 신뢰도를 숨기지 않는다 — 정직한 공백(제품 목표 3) |

### 1.4 화면 문구 (해요체 · 사실만 · 금칙어 13개 배열 준수)

문구는 상수 모듈(`age-copy.ts` — `zone-copy.ts` 관례)로 두고 SC-004 금칙어 테스트를 붙인다.

- 토글 칩: **"노후도"**
- 범례 제목: **"지은 지 30년 넘은 건물 비율"** (스위치: 30년 / 20년)
- 클릭 카드(동): "**이 동은 지은 지 30년 넘은 건물이 1,240동 중 496동이에요(40.0%) ·
  20년 넘은 건물은 812동(65.5%)** · 건축물대장 2026-07 기준" — DA-07 문구 형식 계승, 두 값 병기
- 집계 없음: "**이 동은 집계할 건물이 없어요**(공원·하천 등) · 건축물대장 2026-07 기준"
- 집계 부족: "**사용승인일을 알 수 없는 건물이 많아 비율을 내지 않았어요**(전체 N동 중 M동 결측)"
- 결측 병기(채색된 동): "사용승인일 미상 N동은 계산에서 뺐어요"
- **"노후도가 높다/낮다"의 좋고 나쁨은 쓰지 않는다** — 재개발 기대에는 노후가 유리하게, 실거주에는
  불리하게 읽히는 값이라 판단은 보는 사람의 몫이다(절대 제약 1). 문구는 개수·비율·기준연월까지만.

### 2.2 채택 제안 — OA-21136, 그리고 이유

1. **인증키·계정·사람 손이 전부 불요** — 취득 경로가 OA-22712(DA-13 채택 원천)와 동일한
   `datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do` POST다(실측: `infId=OA-21136&seq=6&infSeq=3`).
   **기존 OA-22712 임포터 계획과 다운로드 코드를 공유**할 수 있다. 브이월드 30335가 로그인 때문에
   월 1회 수동 드롭 폴더(DA-09)인 것과 결정적으로 다르다.
2. **라이선스가 깨끗하다** — 공공누리 1유형(NC·ND 없음). 현 P0 폴리곤(30335, CC BY-NC-ND)보다
   조건이 좋고, 상용 전환 체크리스트(DA-12)의 재점검 대상에도 들어가지 않는다.
3. **서울만, 10.61MB** — 전국 976MB(토지이음)를 매월 받는 비용이 없다.
4. **좌표계·인코딩이 OA-22712와 동일 계열** — PRJ 원문 `Korean_1985_Modified_Korea_Central_Belt`
   (Bessel, 페이지 메타 표기 EPSG:5174), cp949. OA-22712 적재에서 확정할 변환 경로를 그대로 탄다.
5. 약점(정직 기록): ① 파일 갱신 실주기 불명(U-A) — 메타는 월간인데 관측 파일은 202602가 최신.
   토지이음(월간 실증)이 폴백으로 있어 봉쇄되지는 않는다. ② "법적 효력 없음·참고자료" 고지 —
   OA-22712와 동일하며, 화면 출처 표기에 그대로 싣는다(DA-13 관례).

    **원천 식별자 기반 upsert가 불가능**하다는 뜻이고, 이것이 §2.5의 전량 교체 채택 사유다.

### 2.4 매핑 규칙 — 채색 버킷 5 + "그 밖"

- 버킷(채색 대상, **법정 세분의 순서 = 명도 사다리의 순서**): ① 전용주거지역(제1·2종 합 — 실측
  47폴리곤뿐이라 별도 스텝의 값어치가 없고, 정확한 종은 클릭 카드가 말한다) ② 제1종일반주거
  ③ 제2종일반주거(7층이하 포함 — 법정 종 기준. 카드에는 "(7층이하)" 원문 그대로) ④ 제3종일반주거
  ⑤ 준주거. **그 밖의 용도지역**(상업·공업·녹지·기타)은 채색하지 않고 중립 표시(§4) — 사용자
  질문("몇 종 주거지역인지")의 대상이 주거 세분이고, 상업지 등의 사실은 클릭 카드가 원문으로 답한다.
- 순서를 명도로 인코딩하는 근거: 주거 세분은 국토계획법 시행령이 정한 **법정 순서가 있는 사실**이다
  (건폐율·용적률 상한의 사다리). DA-10이 추진 단계를 투명도 순서로 인코딩한 것과 같은 논리 —
  "순서를 순서로 인코딩하는 것은 판단이 아니다".
- 매핑 우선순위(§2.3 품질 실측의 귀결): ① `SCLAS_CL` 코드 사전(동봉 xlsx 기준: UQA111·112 →
  전용, UQA121 → 1종일반, UQA122·**UQA124** → 2종일반, UQA123 → 3종일반) ② 공란이면 `MLSFC_CL`
  사전(UQA130 → 준주거, UQA110 → 전용, 나머지 → 그 밖) ③ **사전에 없는 코드·코드-명칭 불일치는
  "미분류" 버킷**(그 밖과 같은 중립 렌더, 카드에 원문 명칭 그대로) + 적재 리포트에 원문 기록.
  **명칭으로 코드를 덮어쓰지 않는다** — 모르는 값을 가까운 버킷에 넣는 순간 허위 사실이 된다
  (stage_sync의 미확인 버킷 원칙과 동일).
- 사전은 코드 안의 명시 dict + pytest(§1.2와 같은 방식). 첫 적재 때 `DISTINCT` 덤프 리포트로 확정.

### 2.5 스키마 제안 (마이그레이션 022 — **이 문서는 제안만, 파일 생성은 구현 WP에서**)

021과 같은 형식: 멱등 DDL(`CREATE TABLE IF NOT EXISTS`), 컬럼 주석에 "왜"를 적는다.

```sql
-- 022_zoning_district.sql (제안)
-- 용도지역(도시지역) 폴리곤. 원천: 서울 열린데이터광장 OA-21136 (12-age-zoning-layer.md §2).
-- redevelopment_zone과 달리 retired_at이 없다 — 원천 식별자(PRESENT_SN)가 유일하지 않아(실측:
-- 8,312행 중 중복 키 41) upsert 키를 만들 수 없고, 이력 요구도 없어 bjd_dong처럼
-- 파일 단위 전량 교체(단일 트랜잭션)한다.
CREATE TABLE IF NOT EXISTS zoning_district (
    id              BIGSERIAL PRIMARY KEY,
    source          TEXT NOT NULL,            -- 'SEOUL_OA21136' (폴백 교체 대비 — DA-06)
    base_ym         TEXT NOT NULL,            -- 원천 파일 기준연월(YYYY-MM). 화면 출처 표기까지 운반
    lclas_cl        TEXT,                     -- 대분류 코드 원문 (UQA100 등)
    mlsfc_cl        TEXT,                     -- 중분류 코드 원문. 소분류 공란 행(실측 25%)의 매핑 키
    sclas_cl        TEXT,                     -- 소분류 코드 원문 (UQA121 등). 공란 허용 — 원천이 그렇다
    zone_name_raw   TEXT,                     -- DGM_NM 원문. 코드-명칭 불일치의 증거 보존(수집기 관례)
    zoning_bucket   TEXT,                     -- 매핑 결과 버킷. NULL = 미분류(중립 렌더) — 추측 배정 금지
    geom            geometry(MultiPolygon, 4326),
    area_m2         NUMERIC,                  -- DGM_AR 원문
    notice_sn       TEXT,                     -- NTFC_SN 고시번호(관측 표본 다수 공란)
    collected_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS zoning_district_geom_idx ON zoning_district USING GIST (geom);
CREATE INDEX IF NOT EXISTS zoning_district_bucket_idx ON zoning_district (zoning_bucket);
```

- 물건×용도지역 사전계산(`auction_item_zoning`)은 **이번 범위에 넣지 않는다**(P2 제안) —
  이번 요청은 지도 레이어이고, 상세 문장까지 넓히면 EP-3 계약 변경이 따라온다. 넣게 되면
  용도지역은 배타 분할이라 `ST_Contains`(auction_item_dong과 같은 기준)를 쓴다.
- 적재는 `shp_importer`에 `source_kind=SEOUL_ZONING` 추가(04의 "임포터 1개 + 파라미터" 결정 계승).
  다운로드만 드롭 폴더가 아니라 **자동**(OA-22712 계획과 동일 경로) — 건수 대사(±30% 급변 보류)와
  단일 트랜잭션 교체는 기존 관례 그대로.

## 3. C. 필터·버튼 UI — 겹침·범례·줌

현 화면: `apps/web/app/items/map/MapView.tsx`(naver.maps 직접 호출, 좌측 `ItemDetailPanel`).
목록 필터(`ItemFilters.tsx`)는 **목록 화면의 URL 쿼리 필터**라 지도 레이어 토글과 층위가 다르다 —
레이어 토글은 03 UI 방향의 지도 위 `buttonPillTab` 칩 그룹에 얹는다(신규 축 추가가 아니라 기존
계획의 칩 그룹 확장). 지도 SDK 접점은 `zone-layer.ts`와 같은 패턴의 유틸 파일로 격리한다(D-010).

### 3.1 레이어 겹침 — 정면 답: 면(채움) 레이어는 배타다

- **면 레이어(노후도·용도지역)는 라디오** — 동시에 하나만 켜진다. 두 코로플레스를 겹치면 혼색으로
  **두 정보가 모두 소실**된다. 이것은 UI 취향이 아니라 시각 채널의 물리적 한계다.
- **구역 레이어(정비구역·모아타운·재정비촉진 — DA-10 slate 계열)는 체크** — 면 레이어와 동시 허용.
  단, 면 레이어가 켜져 있는 동안 구역 폴리곤은 **fillOpacity를 0으로 내리고 윤곽선만** 그린다
  (`zone-style.ts`에 "면 레이어 동시" 플래그 1개). slate 윤곽 + 채움 코로플레스는 채널이 달라
  (선 vs 면) 공존한다. DA-10의 단계-투명도 인코딩은 이때 잠시 못 보게 되는데, 그 사실을 숨기지
  않는다 — 구역 클릭 카드가 단계를 항상 문장으로 말하므로 사실 접근은 유지된다.
- 20년/30년 전환은 노후도 레이어 내부 스위치(범례 안)다 — 칩을 늘리지 않는다.

### 3.2 토글 칩

- 칩 구성(기존 03 계획 + 이번 확장): 정비구역 · 모아타운 · 재정비촉진 · **노후도** · **용도지역**
  = 5개 — 그룹 ≤7(L-04) 준수. 가로주택·신통(P2)이 진입하면 7 한계라 그때 그룹 분리를 재검토.
- 지도 진입 시 **모두 꺼짐**(T-04 — 기존 화면 불변으로 시작, 03 계승).
- 켜짐 상태는 URL 쿼리에 반영하지 않는다(기존 MapView가 카메라도 URL에 안 싣는 관례 유지 —
  바꾸려면 별도 결정).

### 3.3 범례 — 없으면 코로플레스는 읽을 수 없다

- 면 레이어가 켜진 동안에만 **지도 우하단 고정 카드**로 표시한다. 좌측은 ItemDetailPanel이
  차지하므로 우하단이 유일하게 안전한 코너다(우상단은 네이버 지도 기본 컨트롤 영역).
- 내용: ① 제목(사실 서술 — "지은 지 30년 넘은 건물 비율" / "주거지역 세분") ② 스와치 5개 + 경계값
  (노후도) 또는 스와치 5개 + 명칭(용도지역: 전용주거~준주거) ③ "집계 없음/그 밖" 중립 스와치
  ④ 노후도만: 30년/20년 스위치 ⑤ **출처·기준연월** — "건축물대장 YYYY-MM 기준" /
  "서울시(서울 열린데이터광장) YYYY-MM 기준 · 법적 효력이 없는 참고자료예요"(원천 고지 그대로).
- 스타일: surface 토큰 + hairline 보더(범례는 정보 그래픽이지 행동 레이어가 아니다 — 그림자 정책·
  T-14). 화면당 강조 1곳(L-09)을 범례가 소비하지 않는다.

### 3.4 줌 정책 (04 단순화 정책 계승)

- 단순화 허용오차는 04의 표 그대로: z≤12 → 0.0005 / z13~14 → 0.0002 / z≥15 → 0.00005,
  `ST_SimplifyPreserveTopology` + `ST_AsGeoJSON(geom, 6)`(05 EP-1 관례). 원본 정밀도는 DB 보존.
- **노후도(법정동)**: 서울 법정동은 수백 개 규모라 전 줌 허용 + bbox 필터로 통제. EP-4에
  SC-003과 같은 기준(응답 ≤512KB, 로컬 p95 ≤500ms)을 적용하고 착수 시 실측 보정.
- **용도지역(서울 전역 8,312 피처)**: 법정동보다 한 자릿수 많다. **z≥14에서만 렌더**하고
  z<14에서 칩이 켜져 있으면 "지도를 확대하면 용도지역이 보여요" 안내를 표시한다(FR-005 truncated
  안내와 같은 문법 — 조용한 누락 금지). 피처 상한 상수 `ZONING_FEATURE_LIMIT`는 z14 bbox 실측 후
  확정(05의 `ZONE_FEATURE_LIMIT` 재산정 절차와 동일).
- API는 EP-4(building-age) + 신규 EP-5 `GET /api/map-layers/zoning`(bbox·zoom, class-validator
  DTO, GeoJSON FC + zoning_bucket·zone_name_raw·base_ym 속성) — EP-1과 같은 규약.

### 3.5 클릭·카드

- 면 레이어 폴리곤 클릭 → 사실 카드(§1.4·§2.4 문구). 구역 폴리곤과 겹친 지점은 **zIndex 구역 >
  면**으로 구역 카드가 우선(구역이 더 희소한 정보) — 면 사실은 그 지점의 동/용도지역을 카드
  하단에 한 줄 병기한다.
- 기존 마커·클러스터·물건 클릭 동작은 수정하지 않는다(03 non-goal 계승).

## 4. 팔레트 제안

### 4.1 제약 실측 (왜 새 토큰이 필요한가)

`packages/design-tokens/src/colors.ts`는 28색이 전부이고 **순차(sequential) 계열이 없다.**
같은 지도 화면에서 마커 7색(primary·oculusPurple·metaLink·success·attention·steel·stone)이
소진됐고(DA-10 실측), 구역 레이어가 slate를 가져갔다. 남은 색은 시맨틱(warning·critical 등 —
판단 오독 위험)과 잉크·헤어라인 계열뿐이다. → **토큰 추가 필요.**

### 4.2 제안 토큰 (colors.ts에 추가 — 값은 제안, 확정은 구현 착수 시 실지도 위 재검증)

| 토큰 | 값 | 용도 |
|---|---|---|
| `mapSeq1` | `#e4f2f3` | 순차 1단(가장 밝음) |
| `mapSeq2` | `#a5d6da` | 순차 2단 |
| `mapSeq3` | `#63b4bc` | 순차 3단 |
| `mapSeq4` | `#2f8f9a` | 순차 4단 |
| `mapSeq5` | `#0a6a77` | 순차 5단(가장 진함) |

- **하나의 램프를 두 면 레이어가 공유**한다 — 노후도(1단=낮은 비율 → 5단=높은 비율)와
  용도지역(1단=전용주거 → 5단=준주거). §3.1의 배타 규칙 덕에 한 화면에서 같은 색이 두 뜻을
  갖는 일이 없고(DA-10이 막은 바로 그 문제), 새 색 가족을 하나만 늘린다(규칙 14).
- "집계 없음/그 밖/미분류"는 **채움 없음**(경계선만, `hairlineSoft`) — 별도 토큰 불요.
- fillOpacity는 코로플레스 관례상 0.55 내외의 TS 상수(색이 아니므로 토큰 아님 — DA-10 관례),
  운영 지도 타일 위에서 실측 조정(§7 U-I).

### 4.3 왜 이 색인가 (판단으로 안 읽히는 근거)

1. **틸(청록)은 이 화면에서 비어 있는 색 가족**이다 — 마커 7색·slate 어느 것과도 같은 가족이
   아니다.
2. **적색 계열 단독 사용 회피**(절대 제약 1) — warning/critical/attention 계열을 쓰지 않는다.
   "진한 빨강 = 노후 심각 = 위험"으로 읽히는 팔레트를 원천 차단한다. usage-category와 DA-10이
   시맨틱 색을 회피한 것과 같은 선례.
3. **녹색(success) 계열 회피** — "옅은 초록 = 양호"라는 반대 방향 판단 오독도 같은 이유로 막는다.
4. 틸의 진하기는 "값이 크다/법정 밀도 사다리에서 뒤 순서다"라는 **크기·순서의 인코딩**일 뿐,
   좋고 나쁨의 신호가 아니다(순차 팔레트 = 단일 색상 명도 사다리 — 크기 표현의 표준 문법).

### 4.4 색맹 접근성 (실측 검증)

- 단일 색상 명도 램프는 색상 지각이 아니라 **명도 지각**에 기대므로 구성 자체가 색각이상에
  안전하다(순차 램프의 합격 기준은 명도 단조성 — dataviz 팔레트 검증 도구의 명시 기준).
- 제안값 5단을 팔레트 검증 스크립트로 실측(2026-08-31): 명도 단조 하강 충족, 인접쌍 CVD 분리
  최저 ΔE 9.5(protan, 가장 밝은 1↔2단) PASS, 정상 시각 최저 ΔE 11.4(같은 쌍). 가장 밝은 두 단의
  구분이 상대적으로 얇은 지점은 **2차 인코딩으로 보완**한다 — 폴리곤 경계선(동·구역 경계 stroke),
  범례의 경계값 텍스트, 클릭 카드의 수치. 색만으로 값을 판독하게 만들지 않는다.
- 흰 배경 대비가 3:1 미만인 밝은 단(1~3단)은 넓은 면 채움 전용으로만 쓰고 텍스트·아이콘에는

## 6. 선행 조건과 순서

```
[용도지역 트랙 — 지금 시작 가능 (인증키·계정 불요)]
1. 마이그레이션 022 작성·적용          검증: 2회 연속 실행 멱등(SC-006 방식)
2. 임포터(OA-21136 자동 취득)          검증: 적재 건수 = DBF 피처 수(8,312±, 파일 갱신 시 변동) 대사 로그,
                                            매핑률 리포트(미분류 비율), 좌표 변환 후 서울 bbox 안 여부 표본 확인
3. EP-5 + 웹 레이어·범례·배타 토글      검증: pnpm -r lint/test/build + 신규 순수 함수 테스트
                                            (zoning-style·copy — SC-009 등록 규칙), 응답 ≤512KB 실측
   ※ 3 착수 직전: mapSeq1~5 토큰 추가(디자인 토큰 패키지) + 실지도 대비 확인(U-I)

[노후도 트랙 — 기존 선행 조건 그대로]
1. 사용자 액션 B(브이월드 계정) → 법정동 SHP 수동 취득 → FR-017 적재(bjd_dong)
2. A-V1(세움터/건축HUB 원천 확정) → FR-009 적재(building_age_dong)
3. 분포 실측 → 구간·커버리지 컷라인 확정(§1.2·§1.3)   검증: 표본 3개 동 수동 계산 일치(SC-008 방식)
4. EP-4 구현 + 웹 레이어                              검증: 위와 동일 + C-2(분모 0) 렌더 테스트
```

두 트랙은 독립이다 — 용도지역이 먼저 나가도 노후도를 막지 않고, 역도 같다. 공통 부분(범례·배타
토글 골격)은 먼저 나가는 트랙이 만들고 나중 트랙이 재사용한다.
